# Demo File Guide

A one-paragraph "what this is / what to say" for every file and folder in
this repo, in a sensible order for walking someone through it live.
Companion to the inline comments now in most files — use this for the
handful of files that intentionally have **no** comments added (the true
Playwright-native ones), and as a script if you want one.

Two kinds of files live here, and knowing which is which is the single
most important thing to communicate in a demo:

- **`[NATIVE]`** — generated byte-for-byte by `npm init playwright@latest`
  and never touched. No comments were added to these on purpose: the
  point being demonstrated is that this framework adds structure *around*
  standard Playwright, it doesn't fork or replace it. If you already know
  Playwright, these files should look exactly as you'd expect.
- **`[FRAMEWORK]`** — added on top by this project. These now have inline
  comments explaining what they do and why, so they can carry the
  narration themselves when you open them in VS Code.

## Root

| File | Kind | What to say |
|---|---|---|
| `package.json` | native fields + framework additions | "Native devDependencies (`@playwright/test`, `@types/node`) are untouched; the framework added `scripts` like `typecheck`/`lint`/`validate:flows` and a few more devDependencies for those." Not commented in-file — `package.json` is strict JSON, no `//` comments allowed, so explain this one verbally or point here. |
| `package-lock.json` | native/generated | Standard npm lockfile. Not meant to be read, just committed so `npm ci` in CI is reproducible. |
| `playwright.config.ts` | **[NATIVE]** + 1 line | Byte-identical to `npm init playwright@latest` output except one added line inside `use: {}`: `baseURL: 'https://demo.playwright.dev/todomvc'`. Say: "Every comment, every browser project Playwright generated — untouched. We added exactly one line." |
| `tsconfig.json` | **[FRAMEWORK]** | Now has inline `//` comments explaining every compiler option. Say: "Playwright's test runner doesn't need this at all — it compiles TS on the fly. This exists only for `tsc --noEmit` and for ESLint's type-aware linting." |
| `eslint.config.js` | **[FRAMEWORK]** | Now heavily commented. Say: "This is the deterministic enforcement layer — it's what actually fails the build if someone uses `waitForTimeout()` or forgets an `await`, instead of relying on Copilot to remember the rule." |
| `.gitignore` | **[NATIVE]** block + framework block | The top block (`node_modules/`, `/test-results/`, etc.) is exactly what Playwright generated. A `# Framework additions` block was appended below it, never mixed in. |
| `flows.json` | **[FRAMEWORK]** | Now has a top-level `_readme` and `_fieldNotes` explaining every field — added as separate keys rather than inline comments because this file is read with plain `JSON.parse` (real JSON doesn't support comments) by `scripts/validate-flows.ts`. Say: "This is the one file that has to exist before a test can claim a business flow." |
| `README.md` | **[FRAMEWORK]** | Quick-start instructions. Read this first if picking the repo up cold. |
